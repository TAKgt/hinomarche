# 022 商品編集根拠マイグレーション 適用前レビュー

- 作成日: 2026-08-09
- 状態: SQL作成・PostgreSQL 17一時DBで適用／機能／ロールバック検証済み、本番未適用
- 対象: `supabase/migrations/022_product_editorial_evidence.sql`
- ロールバック: `supabase/rollbacks/022_product_editorial_evidence.rollback.sql`

## 追加するもの

- `product_evidence`テーブル
- 保存時に公開条件を検証するトリガー
- 商品内容・公開状態・判定状態が変わった根拠を非公開へ戻すトリガー
- 公開条件を再確認して必要な列だけ返す`get_public_product_evidence` RPC
- 商品別・公開根拠用インデックス

既存の`products`、`judgments`、商品ページ、アフィリエイトリンク、免責文言は削除・更新しない。
適用直後の根拠行は0件で、公開表示も変わらない。

## 公開条件

`is_public=true`には、次をすべて要求する。

1. 状態が`human_source_checked`
2. 出典種別がメーカー、公的機関、産地団体のいずれか
3. HTTPSの公式URL、出典名、必要最小限の原文、取得日、人手確認日がある
4. 保存した商品入力ハッシュが現在の商品入力ハッシュと一致する
5. 商品が公開中で、判定状態が`current`
6. 現在の入力ハッシュに対応する最新AI判定が整合性検査を通過している

販売元を人が確認しただけの行、AI事前確認の行、商品内容が変わった行は公開できない。

## 権限とデータ送信

- `anon`と`authenticated`はテーブルを直接参照・更新できない。
- 公開RPCは公開条件を満たす列だけを返し、商品ハッシュや内部状態を返さない。
- 外部URLをサーバーが自動取得する処理は追加しない。
- 氏名、メールアドレス、確認者IDなどの個人情報は保存しない。

## 適用時の影響

- 新規テーブルとトリガーの追加だけで、既存行の一括更新はない。
- `products`への更新時、公開根拠が存在する商品だけ非公開化判定が動く。
- 初期状態では根拠行が0件のため、通常の商品更新への追加書き込みは発生しない。
- テーブル作成とトリガー追加時には短時間のDBロックが発生し得るため、バックアップ後、Cron実行時間外に適用する。

## 適用後の匿名集計確認

商品ID、商品名、URLを出力せず、次だけを確認する。

```sql
select
  count(*) as evidence_total,
  count(*) filter (where is_public) as evidence_public,
  count(*) filter (where review_status = 'human_source_checked') as human_checked
from public.product_evidence;
```

初回適用直後の期待値はすべて0件。
